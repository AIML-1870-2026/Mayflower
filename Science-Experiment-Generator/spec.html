Project Summary

A static webpage (HTML, CSS, and JavaScript) that enables a user to interact with an LLM for the purposes of generating grade-appropriate science experiments from a list of available materials. The user provides their OpenAI API key by uploading a .env file — the key is read in-memory only and never stored or transmitted beyond the API call.

The page allows the user to provide a Grade Level via a dropdown (K–2, 3–5, 6–8, 9–12) and a list of Available Supplies via a text input. The model's response is rendered as formatted HTML on the page — similar in feel to the LLM Switchboard: a clean, self-contained static page with no server required.

Key Design Constraints

📄 Static page — HTML, CSS, and JavaScript only

No server, no Node.js, no npm. The page runs entirely in the browser. All dependencies (marked.js, Google Fonts) are loaded from CDN.

🔒 OpenAI models only — no provider switching

Uses gpt-4o exclusively. No Anthropic integration. This is a deliberate architectural choice: Anthropic's API blocks direct browser requests (CORS), so a static page with no backend cannot use it. OpenAI allows browser-to-API calls — that's why this project is OpenAI-only.

💬 Unstructured responses — free-form text only

The model returns free-form text. No response_format: json_object, no schema templates, no structured output. This project uses unstructured (free-form) responses only.

✨ Markdown rendering

The model's response includes markdown formatting (bold, lists, headings, etc.). The app renders this as properly formatted HTML using marked.js — not raw text.

🔑 API keys loaded from .env — in-memory only

The user uploads a .env file; the key is read once via FileReader and stored in a JS variable. Never written to localStorage, cookies, or any server. A direct paste field is also provided — same in-memory-only behavior.

Stretch Challenges Implemented

1
Quick Supply Selector

A grid of clickable chips in three groups (Kitchen, Craft & Office, Science & Outdoor) lets users select common household supplies with one click. Selected chips sync into the supplies textarea; users can still type freely.

2
Difficulty Rating

The system prompt instructs the model to include a ## Difficulty section with one word: Easy, Medium, or Hard. A regex parses this and displays it color-coded in the metrics row (green / amber / red).

3
Experiment History

A "Save to history" button stores each result in-memory as collapsible accordion items, showing grade level, difficulty, supplies used, timestamp, token count, and the full formatted experiment.
